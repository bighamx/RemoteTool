# Codex 原生模块

入口：更多 → Codex。底部导航为系统、远程、文件、Hermes、更多；Docker 位于更多。

## 接入方式

手机经当前设备的 `/api/codex/*` 接口连接，沿用 RemoteTool 登录和所选连接通道。服务端以桌面登录用户身份启动同一 WebApi 程序的 `--codex-bridge` 模式，再以 stdio JSON-RPC 连接本机 `codex app-server`。桥接只监听随机本机回环端口，用私有随机令牌认证。Codex 模块的运行代码全部是 C# 和 Kotlin，不需要 Python。

本机已验证 Codex CLI 0.160.0。初始化启用实际协议的 experimentalApi；能力以安装版本为准。模型目录是可选目录，不能作为账号已获得全部模型权限的证明。

## 会话与任务

- 列出现有 CLI、IDE 和 app-server 会话，分页、读取历史、新建、改名、删除。
- 服务端及手机按会话 ID 合并重复记录，避免同一会话的多个日志记录导致原生列表崩溃。读取当前模型允许桌面进程同时写入日志，忽略尚未写完的最后一行；辅助信息缺失不阻止打开会话。
- 新建选择已有项目、新项目或无项目，随后进入默认时间名称的会话，点击标题后可改名。项目可包含多个目录，恢复保留全部目录；无项目使用独立目录。已有会话先只读历史，发送时调用 thread/resume 接续。
- turn/start 提交文字和本机图片输入，工具由电脑上的完整 Codex 执行。显示回复、工具进度、审批、用户问题和停止操作。
- 提交使用持久请求标识。重复 POST 返回原任务，不盲目重发操作。SSE 仅重连 GET，终态由任务查询确认。
- 任务记录中的 started 不能单独证明仍在执行。桥接重启会把失去跟踪的旧任务收束为结果待核对；读取及插话前核对当前连接是否仍加载该会话。多端 active-run 仅返回已核对的运行任务及状态，不把无法读取的旧 ID 当作活跃任务。
- 写入失败返回 code 和 delivery：rejected 表示本次未写入，手机撤回本地气泡并保留草稿、附件；unknown 表示响应丢失或超时，手机保留请求标识并提示核对真实历史。明确失败的旧插话不再混入会话记录。运行状态超过 30 秒未更新时暂停计时显示。
- “中断并接管”只针对所选会话，通过任务 ID 检查阻止中断后来启动的另一轮任务。确认原任务结束后尝试恢复手机写入，桌面仍持有空闲写锁时使用桌面协作。不可访问的独立所有者会明确提示退出原客户端；不强杀进程、不删除锁，也不自动发送草稿。
- 原生写入采用每会话独立的 app-server 连接，目录、账户及配置查询使用单独的管理连接。完成后关闭本服务为该会话创建的连接，真正释放写锁；不会将 thread/unsubscribe 的 30 分钟空闲保留误认为已释放。尚未写入第一条消息的新会话保留创建连接，以免丢失尚未落盘的初始状态。
- 桌面持有空闲会话写入锁时，手机通过已安装桌面的 IPC follower 接口发起回合，由同一个写入者执行。回复、工具进度、用户提问、审批与停止同步给手机，不删除锁文件或结束桌面进程。独立 CLI 持有锁且没有桌面协作所有者时返回占用说明。
- `/compact` 及输入框快捷命令中的“压缩上下文”只针对当前聊天，右上角菜单不显示压缩入口。桌面持有写入锁时委托其执行，根据实际压缩记录确认结果，超时不自动再次压缩。
- 聊天显示当前上下文 token 数和模型窗口，使用最后一次请求用量，不使用会话累计计费量。异步问题的回答保留官方 questionItemId 与结构化回复标签，桌面可关联到原问题；手机仅显示问题及答案。提交中与已接受的问题不会被轮询重新弹出。阻塞问题使用正式用户输入响应。
- 运行中的手机任务支持插话：官方 turn/steer 或桌面 follower steer。使用独立请求标识，重复请求返回已接受状态，结果不明时不再次发送。
- 新建、模型选择及任务完成后释放手机 app-server 的空闲订阅。新手机会话及删除事件通过桌面 IPC 更新目录。新项目来自官方项目数据库，桌面保存项目的界面缓存由桌面管理。
- 会话列表及每个文件目录保存滚动位置，Windows 路径缓存统一尾部分隔符和大小写。
- 工作目录默认是桌面用户的 Documents/Codex/Mobile；已有会话保留其原工作目录。
- Provider/模型选择复用两步界面。Provider 要求 Responses API 兼容，已有密钥不返回手机；新密钥只在私有配置目录保存并注入子进程环境。全局配置修改通过官方 config/batchWrite，在修改前备份 config.toml。

## 账户及 ChatGPT 工作空间

按用户提供的切换方案，共享一个 CODEX_HOME，保留会话、索引、配置和项目资料，切换只针对 auth.json。

- 库位于桌面用户的 `~/.codex-switch/accounts.json`，按邮箱和 chatgpt_account_id 识别身份。同邮箱的个人／团队记录可共存。
- 首次保存当前原生登录，后续也可点“保存电脑当前登录”。登录记录不包含在手机响应中，手机仅获得邮箱、身份、套餐及本地记录 ID。
- 新登录使用官方设备码流程。捕获进程使用私有临时 CODEX_HOME，不覆盖电脑现有 auth.json；授权完成后只保存身份记录。新身份需由用户在官方页面授权。
- 界面以当前邮箱为账户边界，仅列出其个人／团队工作空间，标明当前使用的身份和切换按钮。切换过程显示不可取消的遮罩，禁止重复点击及返回。
- 切换先核对目标身份，再自动结束当前 Windows 会话中的旧 Codex 进程和属于 Codex 安装包的桌面进程；收回最新令牌、切换身份、重建并初始化 app-server，最后重新打开桌面 Codex。不结束其他用户会话或独立的 ChatGPT 安装。
- 切换先回收源身份最新凭据并备份，再原子替换 auth.json，核对身份并重建桥接连接。来源身份未保存时拒绝覆盖。失败时恢复原登录。
- 配置和历史不参与切换；移除账户记录也不会移除电脑原生登录。凭据库、备份及桥接连接目录由 Windows ACL 限制为桌面用户和 LocalSystem。
- app-server 意外退出后自动恢复连接，不自动重发任务；切换失败恢复源身份及连接。释放后的进程状态检测和重复释放均安全。
- 工作空间列表显示已授权保存的身份，不将 API 组织列表错误当成 ChatGPT 工作空间。添加另一工作空间时在官方登录流程选择目标个人／团队身份。
- 5 小时及周额度来自 account/rateLimits/read，展示剩余百分比和重置时间。缺失数据为“暂无数据”，不伪造额度。
- 切换对话框在个人／团队各自卡片内显示独立用量，可手动刷新。当前身份使用现有连接；其他已保存身份在受 ACL 保护的临时目录中查询并核对工作空间，结束后清理目录，不切换原生登录或修改共享配置。若查询刷新了凭据，只更新仍匹配原记录的保存身份，防止覆盖更新的授权；成功用量缓存 30 秒。

## 附件

沿用手机原生附件 UI：500 MiB 上传、Markdown、图片缩放、视频缩略图及播放、音频/文本预览、文档交给本机应用打开、单独下载及清理手机副本。

Codex 附件目录独立于 Hermes：ProgramData/ChuckieHelper/codex-attachments。图片通过 localImage 输入；其他文件保留本机路径供工具读取。生成文件写到独立回合的 outbox，MEDIA 标记转换为可点击附件。服务端每日清理超过三个日历月且大于 100 MiB 的附件，避开链接和正在使用的文件。
