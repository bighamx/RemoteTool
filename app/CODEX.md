# Codex 原生模块

## 主 App 与手机操控精简版

`mobile` 与 `phonecontrol` 共享 `mobile/src/main/java`、`phone-shared/src/main/java` 和 `shared-dependencies.gradle`。精简版只用 `BuildConfig.PHONE_COMPANION` 筛选入口；已有的设备、云账户、配置、手机操控、端口转发、日志及自启动页面必须直接复用，不另写同功能页面，后续 UI 与协议修改要同时适用两版。云登录共用应用与公共 PKCE 客户端，以随机 state 前缀和安装签名匹配路由回正确 App，再由各自私有状态完成校验。

手机工具 schema 2 提供 `phone_begin_ui`、`phone_end_ui`、`phone_disconnect`、`phone_notify_user`、`phone_get_user_reply`。所有手机操作与核验完成后，最后调用 `phone_disconnect`，立即撤下本 Agent 的连接／操作提示及待处理消息；服务和授权保留，其他 Agent 不受影响。`phone_end_ui` 仅结束 UI 声明，不等于断开；`ping` 和工具发现不能重新点亮提示，新工具调用或 `initialize` 才恢复。每个 Web 绑定单独维护声明和回执；回执未完成、过期或丢失都不能当作用户已完成。顶部提示与 HyperOS 通知使用同一状态；普通前台服务继续共用一条后台通知，协助消息独立显示。超级岛使用官方接口，除系统协议和 `canShowFocus` 开关外仍需小米平台 App ID、证书及鉴权通过；不能把开关开启当成上岛成功，不伪装媒体或改系统白名单。完整调用约定在 `tools/PhoneTools/README.md`。

入口：更多 → Codex。底部导航为系统、远程、文件、Hermes、更多；Docker 位于更多。

手机工具的公共可选参数 `explanation` 用于简短说明动作及目的（最多 240 字符），统一由共享引擎和悬浮提示处理，不传给底层操作后端，也不计入请求去重摘要。两版 App、Hermes 插件 schema、MCP instructions 和按能力注入的提示词必须同步；普通说明不需要另调消息工具，用户协助仍使用带回执的 help 消息。

## 接入方式

手机经当前设备的 `/api/codex/*` 接口连接，沿用 RemoteTool 登录和所选连接通道。服务端以桌面登录用户身份启动同一 WebApi 程序的 `--codex-bridge` 模式，再以 stdio JSON-RPC 连接本机 `codex app-server`。桥接只监听随机本机回环端口，用私有随机令牌认证。Codex 模块的运行代码全部是 C# 和 Kotlin，不需要 Python。

本机已验证 Codex CLI 0.160.0。初始化启用实际协议的 experimentalApi；能力以安装版本为准。模型目录是可选目录，不能作为账号已获得全部模型权限的证明。

## 会话与任务

### 双向端口转发

- 我的设备/更多 → 开机自启，用户可开启解锁后自动恢复手机工具、手机工具 Web 转发通道及 TCP/UDP 端口转发；默认总开关关闭。BOOT_COMPLETED/MY_PACKAGE_REPLACED 启动独立 specialUse 恢复服务，不弹出 Activity、不自动授权无障碍/Root/Shizuku。网络未就绪时退避等待；先验证保存电脑的设备身份，再使用 Android Keystore 中现有凭据验证/续签，不另存明文密码或令牌。手机工具转发恢复时不会重启已开启的本地监听。手动停止会暂停本轮该功能的恢复，关闭自启只取消待恢复任务，不停止已经运行的业务服务。部分厂商还需手动放行系统自启动/后台运行权限。

- App 更多 → 端口转发，为当前电脑配置 TCP/UDP 规则。手机 → 电脑：手机监听本地端口，电脑连接目标 IP/主机名；电脑 → 手机：电脑监听端口，手机连接目标。目标可为拨号端可达的局域网设备，不限于自身；主机名也在拨号端解析。不使用 VPN，不自动扫描网段或修改系统路由。
- 手机主动连接已登录设备的 `/ws/tunnel`，复用网站入口、登录凭据及通道地址，独立于终端、键鼠与手机控制 WS。默认监听 `127.0.0.1`；明确勾选“允许其他设备访问（所有网卡）”后绑定 `0.0.0.0`，局域网其他设备可用监听端的 LAN IP 访问。监听端口 1024–65535，目标端口 1–65535，需由设备防火墙允许相应入站访问。
- 规则按设备保存在手机；一次仅运行一个设备的隧道，每连接最多 32 条规则、64 个业务连接/UDP 会话。规则在停止后编辑。后台由独立 specialUse 前台服务保持，切换页面不停止。网络切换及断线采用 1–30 秒退避重连，20 秒 WS Ping；重连后重建监听，原 TCP 连接不跨 WS 代际续传。被强制停止/杀进程后需重新开启。认证过期尝试沿用当前设备的自动续签回调，失败则停止。
- 二进制协议 v1：12 字节大端头 `[version:u8,type:u8,reserved:u16,channel:i32,aux:i32]` 后接 payload；type=1 OPEN(aux=ruleId)、2 OPENED、3 DATA、4 FIN、5 CLOSE、6 WINDOW(aux=consumedBytes)、7 DATAGRAM、8 ERROR。手机创建奇数 channel，电脑创建偶数 channel，编号单调递增。先 JSON configure(version/client_id/run_id/name/rules)，电脑绑定完成回复 ready；每个 OPEN 等 OPENED 后才发业务数据，目标只能来自已确认的配置规则。run_id 在每次手动开启时生成，网络重连沿用；电脑停止后拒绝该 run_id 重连，防止停止通知丢失导致自动重开。
- TCP 分块最多 16 KiB，双向初始窗口各 64 KiB，使用按字节计量的环形接收缓存，落入目标 socket 后回报 WINDOW；FIN 排在数据后处理并关闭对应写半部。限流包含逐流接收窗口、有界消息队列及手机 1 MiB WS 发送队列水位。UDP 保留数据报边界，最大 65507 字节，每源端点独立会话，60 秒空闲回收；UDP 进出队列各最多 16 包/64 KiB，手机/电脑监听端的待发包超过 2 秒则丢弃。UDP over WS 仍受 TCP 重传和队头阻塞影响。
- 电脑网站“端口转发”(`/Tunnels`) 可查看连接/规则/流量并停止手机隧道；`GET /api/tunnels` 与 `POST /api/tunnels/{id}/stop` 沿用网站认证。电脑停止会向手机发 stopped，手机停服务、不自动重开。没有第三方公网中继，转发数据不落盘；监听结束会释放两端 socket。

### 会话与任务行为

- App 在 Application 初始化时安装全局未捕获异常处理器，主线程和后台线程崩溃同步落盘后交回系统退出；不吞掉致命错误、不自动重启。日志在手机私有目录 `files/crash-reports`，最多 20 份、每份最多约 1 MiB，包含版本、线程堆栈、内存信息及最近页面/Activity 生命周期。Android 11+ 下次启动补收系统可提供的崩溃、原生崩溃、ANR 和内存不足等退出记录；系统 trace 不一定可用。我的设备/更多 → 诊断日志，可查看、导出 ZIP 和清空，不自动上传；Release 混淆映射按版本保存在 `app/mobile/build/outputs/crash-mappings`，分析堆栈时使用对应版本。

- 列出现有 CLI、IDE 和 app-server 会话，分页、读取历史、新建、改名、删除。
- 服务端及手机按会话 ID 合并重复记录，避免同一会话的多个日志记录导致原生列表崩溃。读取当前模型允许桌面进程同时写入日志，忽略尚未写完的最后一行；辅助信息缺失不阻止打开会话。
- 新建选择已有项目、新项目或无项目，随后进入默认时间名称的会话，点击标题后可改名。项目可包含多个目录，恢复保留全部目录；无项目使用独立目录。已有会话先只读历史，发送时调用 thread/resume 接续。
- turn/start 提交文字和本机图片输入，工具由电脑上的完整 Codex 执行。显示回复、工具进度、审批、用户问题和停止操作。
- 提交使用持久请求标识。重复 POST 返回原任务，不盲目重发操作。SSE 仅重连 GET，终态由任务查询确认。
- 任务记录中的 started 不能单独证明仍在执行。桥接重启会把失去跟踪的旧任务收束为结果待核对；读取及插话前核对当前连接是否仍加载该会话。多端 active-run 仅返回已核对的运行任务及状态，不把无法读取的旧 ID 当作活跃任务。
- 写入失败返回 code 和 delivery：rejected 表示本次未写入，手机撤回本地气泡并保留草稿、附件；unknown 表示响应丢失或超时，手机保留请求标识并提示核对真实历史。明确失败的旧插话不再混入会话记录。运行状态超过 30 秒未更新时暂停计时显示。
- “中断并接管”只针对所选会话，通过任务 ID 检查阻止中断后来启动的另一轮任务。确认原任务结束后尝试恢复手机写入，桌面仍持有空闲写锁时使用桌面协作。不可访问的独立所有者会明确提示退出原客户端；不强杀进程、不删除锁，也不自动发送草稿。
- 原生写入采用每会话独立的 app-server 连接，目录、账户及配置查询使用单独的管理连接。完成后关闭本服务为该会话创建的连接，真正释放写锁；不会将 thread/unsubscribe 的 30 分钟空闲保留误认为已释放。尚未写入第一条消息的新会话保留创建连接，以免丢失尚未落盘的初始状态。
- 桌面持有空闲会话写入锁时，手机通过已安装桌面的 IPC follower 接口发起回合，由同一个写入者执行。回复、工具进度、用户提问、审批与停止同步给手机，不删除锁文件或结束桌面进程。独立 CLI 持有锁且没有桌面协作所有者时返回占用说明。
- `/compact` 及输入框快捷命令中的“压缩上下文”只针对当前聊天，右上角菜单不显示压缩入口。桌面持有写入锁时委托其执行，根据实际压缩记录确认结果，超时不自动再次压缩。
- 聊天显示当前上下文 token 数和模型窗口，使用最后一次请求用量，不使用会话累计计费量。异步问题的回答保留官方 questionItemId 与结构化回复标签，桌面可关联到原问题；手机仅显示问题及答案。提交中与已接受的问题不会被轮询重新弹出。阻塞问题使用正式用户输入响应。
- 运行中的手机任务支持插话：官方 turn/steer 或桌面 follower steer。使用独立请求标识，重复请求返回已接受状态，结果不明时不再次发送。
- 新建、模型选择及任务完成后释放手机 app-server 的空闲订阅。新手机会话及删除事件通过桌面 IPC 更新目录。新项目来自官方项目数据库，桌面保存项目的界面缓存由桌面管理。
- 会话列表仅保存可见项索引与像素偏移；会话重排不按会话 ID 锚定恢复。文件目录保留原有滚动位置，Windows 路径缓存统一尾部分隔符和大小写。
- Hermes 运行回执可能比 SSE 事件流存活更久；事件流缺失时，从当前会话的 activity 快照恢复已落盘工具进度，不将事件流 404 视为任务结束。快照校验 run、会话、连接与有效期，避免显示另一轮任务的进度。
- Hermes 会话列表顶部可切换已有 Profile，按设备记住选择；每个 Profile 使用独立 ViewModel、历史缓存、草稿、附件、队列与滚动状态。切换只改变当前客户端的请求范围，原任务继续执行，不修改 Hermes 的 active_profile、不重启网关。外部分享沿用该设备选中的 Profile。
- Hermes 列表菜单是 Profile/网关管理入口，会话菜单仅保留会话操作并提供管理页跳转。管理页编辑 memories/MEMORY.md、memories/USER.md、SOUL.md，提供预览、文件版本冲突检查、原子保存和备份恢复；工作目录 AGENTS.md 不冒充 Profile 全局指令。配置与网关管理分区，网关操作影响全部 Profile。
- Windows 网关维护通过桌面用户的一次性计划任务托管，状态和原始日志保存在 Hermes Home/cache/remotetool-maintenance。暂停接单后核对全部 Profile 的有效任务租约及网关活跃工作，安全排空后请求正常退出，禁止强杀。更新使用官方 update --yes --no-gateway-restart；使用官方备份、暂存和恢复本地修改流程，--yes 自动确认配置迁移与恢复暂存修改；不额外导出差异或阻止有本地修改的更新，不强制更新、删除未知锁或任务。完成要求新 PID、运行代码 SHA、平台连接及 API 均核对成功。App/Web 每两秒增量读取日志，关闭界面不取消维护；等待阶段可取消，最多等待 30 分钟。维护状态未知时不自动重试。
- 服务端 `GET /api/hermes/profiles` 列出已有 Profile 及可用状态；命名 Profile 使用 `/api/hermes/profiles/{profile}/...`，代理到 Hermes `/p/{profile}/...`，密钥仅在服务端从该 Profile 的 `.env` 读取。管理子进程、本地数据库、活跃任务、上下文缓存、自动标题与附件均隔离；默认 Profile 保留原接口和数据位置。缺少独立 API_SERVER_KEY 或未被网关服务的 Profile 不可切换；不会自动创建密钥或修改网关配置。Web 按站点保存选择，并通过重新载入页面切断旧订阅。
- 工作目录默认是桌面用户的 Documents/Codex/Mobile；已有会话保留其原工作目录。
- Provider/模型选择复用两步界面。Provider 要求 Responses API 兼容，已有密钥不返回手机；新密钥只在私有配置目录保存并注入子进程环境。全局配置修改通过官方 config/batchWrite，在修改前备份 config.toml。
- 模型显示和发送使用同一份有效配置。Codex 的 `custom` 是实际 Provider ID，不能当作占位值隐藏后显示另一个全局提供方。新消息携带 `model_settings`（provider/model/reasoning_effort/service_tier）快照，服务端校验后优先使用；待确认消息保留原快照，不因切换会话或修改模型而改变同一请求标识的内容。
- `model-selections.json` 仅持久化每会话偏好，不得使旧路由覆盖用户选择。读取及恢复前校验失效 Provider、已停用的 CC Switch 管理代理、过期地址覆盖；修复后写回偏好并在下次使用前释放本服务的旧空闲连接。仍有效的独立第三方选择保留；显式提交已停用代理返回 `model_settings_changed`，不暗中换 Provider、不发送模型消息、不重试推理。运行中及原生队列中的连接不因修复被中断。

## 账户及 ChatGPT 工作空间

按用户提供的切换方案，共享一个 CODEX_HOME，保留会话、索引、配置和项目资料，切换只针对 auth.json。

- 库位于桌面用户的 `~/.codex-switch/accounts.json`，按邮箱和 chatgpt_account_id 识别身份。同邮箱的个人／团队记录可共存。
- 首次保存当前原生登录，后续也可点“保存电脑当前登录”。登录记录不包含在手机响应中，手机仅获得邮箱、身份、套餐及本地记录 ID。
- 新登录使用官方设备码流程。捕获进程使用私有临时 CODEX_HOME，不覆盖电脑现有 auth.json；授权完成后只保存身份记录。新身份需由用户在官方页面授权。
- 界面以当前邮箱为账户边界，仅列出其个人／团队工作空间，标明当前使用的身份和切换按钮。切换过程显示不可取消的遮罩，禁止重复点击及返回。
- 切换先核对目标身份，再自动结束当前 Windows 会话中的旧 Codex 进程和属于 Codex 安装包的桌面进程；收回最新令牌、切换身份、重建并初始化 app-server，最后重新打开桌面 Codex。不结束其他用户会话或独立的 ChatGPT 安装。
- 切换先回收源身份最新凭据并备份，再原子替换 auth.json，核对身份并重建桥接连接。来源身份未保存时拒绝覆盖。失败时恢复原登录。
- 配置和历史不参与切换；移除账户记录也不会移除电脑原生登录。凭据库、备份及桥接连接目录由 Windows ACL 限制为桌面用户和 LocalSystem。
- app-server 意外退出后自动恢复连接，不自动重发任务；切换失败恢复源身份及连接。释放后的进程状态检测和重复释放均安全。
- 工作空间列表显示已授权保存的身份，不将 API 组织列表错误当成 ChatGPT 工作空间。添加另一工作空间时在官方登录流程选择目标个人／团队身份。
- 5 小时及周额度来自 account/rateLimits/read，展示剩余百分比和重置时间。缺失数据为“暂无数据”，不伪造额度。
- 切换对话框在个人／团队各自卡片内显示独立用量，可手动刷新。当前身份使用现有连接；其他已保存身份在受 ACL 保护的临时目录中查询并核对工作空间，结束后清理目录，不切换原生登录或修改共享配置。若查询刷新了凭据，只更新仍匹配原记录的保存身份，防止覆盖更新的授权；成功用量缓存 30 秒。

## 附件

沿用手机原生附件 UI：500 MiB 上传、Markdown、图片缩放、视频缩略图及播放、音频/文本预览、文档交给本机应用打开、单独下载及清理手机副本。

助手 Markdown 链接的目标为绝对本机文件路径时，App 同时提供附件卡片，并将原链接的点击行为接入附件预览。排除用户消息、代码块和行内代码。已有附件优先复用，其余文件使用原有文件管理接口核对并读取，无需升级设备服务。Markdown 文件复用 Markwon 预览，无需安装其它阅读器。

Codex 附件目录独立于 Hermes：ProgramData/RemoteTool/codex-attachments。图片通过 localImage 输入；其他文件保留本机路径供工具读取。生成文件写到独立回合的 outbox，MEDIA 标记转换为可点击附件。服务端每日清理超过三个日历月且大于 100 MiB 的附件，避开链接和正在使用的文件。
